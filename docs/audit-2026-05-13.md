# Smriti Audit - 2026-05-13

Scope: repository structure, Rust library, Tauri shell, database migrations, tests, GitHub Actions, release scripts, and obvious security-sensitive file/network paths.

## Findings

### High: fresh database schema version drift

`src/db/schema.rs` created the current v21 schema, including `face_processing_stats`, but inserted `schema_version = 20`. Any path that creates a fresh database and does not immediately call `run_migrations` leaves the DB mislabeled. That makes future migrations harder to reason about and can produce CI-only failures when tests assume migration state.

Status: fixed by recording schema version 21 and making the integration test compare against `MAX_KNOWN_SCHEMA_VERSION`.

### Medium: migration coverage was too narrow

`test_v15_composite_indexes_present_and_used` checked a fresh schema plus `run_migrations`, but it did not prove an existing v14 database receives the v15 composite indexes. That left room for fresh-schema/migration drift.

Status: fixed by adding a v14-to-latest integration test that asserts all v15 composite indexes and the final schema version.

### Medium: Tauri capability surface is broad

`src-tauri/capabilities/default.json` grants `fs:default`, `shell:default`, `dialog:default`, `os:default`, and clipboard access to the main window. For a local photo manager this may be acceptable, but it is broader than ideal if a renderer bug or dependency XSS appears.

Recommendation: narrow permissions to exact commands and filesystem scopes used by the UI. Keep shell access especially constrained.

### Medium: asset protocol scope is effectively whole-disk for common paths

`src-tauri/tauri.conf.json` enables asset protocol access with broad globs including `**`, hidden files, `$HOME/**`, `/media/**`, and `/mnt/**`. This matches the app's need to display local photos, but it also increases the blast radius of a renderer compromise.

Recommendation: replace global `**` with a runtime allowlist rooted at the selected library and generated cache directories if Tauri supports the required flow.

### Medium: permanent delete trusts stored relative paths

`TrashService::permanent_delete` joins `drive_root` with `photos.file_path` and removes the resulting file. Normal scanner paths should be relative, but the DB is on the user-controlled drive and can be edited. A malicious or corrupt DB row containing `../...` could target files outside the library root.

Recommendation: add a shared safe-join helper that rejects absolute paths, parent components, and Windows prefixes before any open/delete operation based on DB paths.

### Medium: remote GPU bridge can send face crops off-device

`RemoteEmbedder` uploads face crops to a configured HTTP(S) endpoint. That is a privacy-sensitive feature for an offline-first app. The code validates model compatibility but not transport security beyond accepting any URL configured elsewhere.

Recommendation: make this opt-in in UI copy, prefer HTTPS, warn on plain HTTP except localhost, and document exactly what is sent.

### Low: release asset pack downloads are unauthenticated beyond TLS

Release workflow and setup scripts download ONNX models, GeoNames files, and ONNX Runtime archives from third-party URLs without pinned checksums. TLS helps but does not protect against upstream replacement or account compromise.

Recommendation: pin SHA256 checksums in scripts/workflows and verify before packaging.

### Low: local release scripts are stale versus Tauri release workflow

`scripts/release_local.sh` still contains older cargo-deb/AppImage logic while `.github/workflows/release.yml` uses Tauri. This causes local "release verification" to differ from tag CI.

Status: added `scripts/ci_local.sh release` to exercise the current frontend + Tauri/Rust release path locally. Consider retiring the older script branches after the new script is adopted.

## Local Verification Workflow

Before a normal push:

```bash
scripts/ci_local.sh ci
```

Before pushing a release tag on Linux:

```bash
scripts/ci_local.sh release
```

Before a high-confidence release:

```bash
scripts/ci_local.sh all
```

To wire the normal CI check into Git:

```bash
ln -sf ../../scripts/pre-push .git/hooks/pre-push
```

This does not replace GitHub Actions. It shifts most deterministic failures left. Cross-platform release confidence still requires Windows and macOS runners, either through PR CI, a draft-release branch, or a manual workflow before tagging.
